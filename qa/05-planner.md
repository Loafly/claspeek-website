# 05. 일정·D-Day

## 1. 도메인 정의

회원이 본인의 일정을 관리하고, 중요한 날까지의 D-Day를 추적하며, 학교 행사를 확인하고 출석 체크로 활동 이력을 쌓는 도메인.

## 2. 핵심 개념·용어

- **일정**: 회원의 개인 일정. 시작/종료 일시, 종일 여부, 메모를 가진다. 본인만 조회·수정.
- **D-Day**: 특정 날짜까지 남은(또는 지난) 일수를 카운트하는 기념·목표 표시.
- **학교 행사(Event)**: 학교 단위로 안내되는 공식 행사.
- **출석**: 행사 또는 일일 출석 체크 기록. 연속 출석 일수가 함께 집계된다.

## 3. 기능 요구사항

### 3.1 일정 관리

#### 월간 일정 조회

> 회원이 한 달치 일정을 한눈에 볼 수 있다.

**누가**: 본인

**정상 흐름**
1. 진입 시 현재 월이 표시되며, 일정이 있는 날짜에 마커가 표시됨
2. 좌/우 스와이프 또는 헤더 버튼으로 월 이동
3. 날짜 클릭 시 해당 날의 일정 목록 표시

**예외 처리**

| 상황 | 결과 |
|------|------|
| 자정 직전·직후 일정 표시 | 일자 일관성이 유지되어야 함 |
| 빠른 월 이동 | 깜빡임 / 중복 로드 없어야 함 |

#### 일정 등록

> 회원이 본인의 일정을 등록할 수 있다.

**누가**: 본인

**정상 흐름**: 제목·시작/종료 일시·종일 여부·메모 입력 → 등록.

**입력 조건**

| 항목 | 조건 |
|------|------|
| 제목 | 글자수 제한 내, 빈 입력 차단 |
| 시작/종료 일시 | 종료가 시작보다 빠를 수 없음 |
| 종일 여부 | 종일 토글 시 시간 입력 비활성 |
| 메모 | 글자수 제한 내(선택) |

**예외 처리**

| 상황 | 결과 |
|------|------|
| 빈 제목으로 등록 | 등록 차단 |
| 종료 시각이 시작보다 빠름 | 등록 차단 + 안내 |

#### 일정 수정

> 작성자가 본인의 일정을 수정할 수 있다.

**누가**: 본인

**정상 흐름**: 일정 선택 → 수정 → 저장.

#### 일정 완료 표시

> 회원이 일정을 완료 처리하여 진척도를 관리할 수 있다.

**누가**: 본인

**정상 흐름**: 체크박스 탭 → 완료/미완료 토글.

**예외 처리**

| 상황 | 결과 |
|------|------|
| 빠른 연타 | 마지막 상태가 정확히 반영되어야 함 |

#### 일정 삭제

> 작성자가 본인의 일정을 삭제할 수 있다.

**누가**: 본인

**정상 흐름**: 삭제 확인 → 캘린더 마커가 즉시 사라짐.

**정책**: 반복 일정의 단건/모두 삭제 옵션은 운영 정책으로 정의.

### 3.2 D-Day 관리

#### D-Day 등록

> 회원이 시험·기념일 등 특정 날을 D-Day로 등록하여 카운트할 수 있다.

**누가**: 본인

**정상 흐름**: 제목 + 목표 일자 입력 → 목록에 카운터 표시.

**입력 조건**

| 항목 | 조건 |
|------|------|
| 제목 | 글자수 제한 내, 빈 입력 차단 |
| 목표 일자 | 과거 일자 등록 가능 여부는 운영 정책 (D+ 표시 여부) |

#### D-Day 수정·삭제

> 회원이 등록한 D-Day를 수정·삭제할 수 있다.

**누가**: 본인

**정상 흐름**: 본인 D-Day 수정/삭제 → 즉시 반영.

### 3.3 학교 행사·출석

#### 학교 행사 조회

> 회원이 본인 학교의 공식 행사 정보를 확인할 수 있다.

**누가**: 정상 회원

**정상 흐름**: 행사 목록 + 상세 조회.

**정책**: 본인 학교 외 행사 노출 정책은 운영 정책으로 정의.

#### 출석 체크

> 회원이 행사 또는 일일 출석을 기록하여 연속 출석을 만들 수 있다.

**누가**: 본인

**정상 흐름**: 출석 버튼 탭 → 체크 완료, 연속 출석 카운트 갱신.

**정책**: 자정 경계의 출석 처리 기준은 서버 시각.

**예외 처리**

| 상황 | 결과 |
|------|------|
| 동일 일자 중복 체크 | 차단 |

## 4. 알림 발송 명세

| 트리거 | 수신자 | 본문 (예시) | 카테고리 |
|--------|--------|-----------|---------|
| 일정 시작 N분 전(예: 30분 전) | 일정 소유자 | "{일정 제목} 시작 30분 전입니다." | 일정 |
| 본인 학교 행사 등록 | 본인 학교 회원 | "{행사 제목}이 등록되었습니다." | 행사 |
| D-Day 임박(D-N) | D-Day 소유자 | "'{제목}'까지 {N}일 남았습니다." | D-Day |
| 출석 연속 끊김 위기(예: 자정 전 미출석) | 회원 | "오늘의 출석을 잊지 마세요!" | 리마인더 |

**공통 정책**
- 사전 리마인더 시점(N분 전 / N일 전)은 운영 정책으로 정의.
- 야간(예: 22:00~08:00) 발송 차단은 운영 정책에 따라 결정.
- 본인이 수정·삭제한 일정에 대한 리마인더는 즉시 취소.

## 5. 정책·규칙

| 항목 | 값 |
|------|------|
| 시간 기준 | 마감·D-Day·출석 모두 **서버 시각** 기준 |
| 일정의 비공개성 | 작성자만 조회·수정·삭제 가능 |
| D-Day 자정 갱신 | 자정에 카운트가 자동 갱신되거나 새로고침으로 갱신 |

## 6. 도메인 공통 예외

- 디바이스 시간대를 임의 변경한 상태에서도 일정·D-Day·출석이 의도대로 동작.
- 매우 많은(수백 개) 일정이 있는 월의 렌더링 성능.
