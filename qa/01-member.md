# 01. 회원

## 1. 도메인 정의

학생 사용자가 서비스에 가입하고, 학생 신원을 검증받고, 본인의 계정과 프로필을 관리하는 모든 활동을 다루는 도메인. 학생증 검증을 통과한 회원만이 학교 단위 커뮤니티 활동에 참여할 수 있다.

## 2. 회원 상태

| 상태 | 정의 | 가능한 행동 |
|------|------|------|
| 비회원 | 가입하지 않은 사용자 | 앱 소개·로그인·회원가입 진입, 정책 페이지 외부 링크 열람 |
| 가입 진행 중 | 회원가입 일부 단계까지만 완료한 사용자 | 본인의 가입 흐름 이어가기 |
| 검증 대기 | 학생증을 제출했으나 결과가 나오지 않은 사용자 | 검증 결과 대기 안내만 표시, 다른 기능 이용 불가 |
| 검증 거절 | 학생증이 거절된 사용자 | 거절 사유 확인 후 재제출 |
| 정상 회원 | 학생증 검증을 통과한 활성 회원 | 모든 사용자 기능 |
| 일시 정지 | 운영자가 일시 정지한 회원 | 로그인은 되지만 콘텐츠 작성·반응 등 제한 |
| 탈퇴 / 영구 차단 | 본인 탈퇴 또는 운영자 영구 차단 | 로그인 불가 |

## 3. 핵심 개념·용어

- **학생증 인증**: 학생 신원을 증명하기 위해 학생증 사진을 제출하고 운영자가 검토하여 승인 또는 거절하는 절차.
- **닉네임**: 다른 사용자에게 노출되는 표시 이름. 서비스 내 중복 불가.
- **자동 로그인**: 사용자가 명시적으로 로그아웃하지 않는 한, 다음 앱 실행 시 다시 로그인 입력을 요구하지 않는 동작.
- **세션 만료**: 너무 오랫동안 미사용으로 인해 자동 로그인 상태가 풀려 다시 로그인이 필요해진 상태.
- **소셜 로그인**: 외부 사업자(Google / Kakao / Naver / Apple)의 계정으로 본 서비스에 로그인하는 방식.

## 4. 기능 요구사항

### 4.1 회원가입

#### 약관 동의 및 자격증명 입력

> 학생이 이메일·비밀번호와 약관 동의로 가입 절차를 시작할 수 있다.

**누가**: 비회원

**정상 흐름**
1. 이메일 입력 → 즉시 형식·중복 검사
2. 비밀번호와 비밀번호 확인 입력
3. 필수 약관 동의(서비스 약관·개인정보 처리방침). 마케팅 등 선택 약관은 따로 표시
4. 모든 검증 통과 시 다음 단계(기본 정보 입력)로 이동

**입력 조건**

| 항목 | 조건 |
|------|------|
| 이메일 | 일반 이메일 형식, 중복 가입 불가 |
| 비밀번호 | 8자 이상, 영문+숫자 조합 권장 (정확한 정책은 운영팀 확정) |
| 비밀번호 확인 | 비밀번호와 동일해야 함 |
| 필수 약관 | 모두 동의해야 함 |

**예외 처리**

| 상황 | 결과 |
|------|------|
| 이미 가입된 이메일 | "이미 가입된 이메일입니다" 안내, 진행 불가 |
| 비밀번호 불일치 | "비밀번호가 일치하지 않습니다" 안내 |
| 비밀번호 정책 미충족 | 정책 가이드 안내 |
| 필수 약관 미동의 | "다음" 버튼 비활성 |

#### 기본 정보 입력

> 회원의 기본 정보(이름·생년월일)를 등록할 수 있다.

**누가**: 가입 진행 중

**정상 흐름**: 이름과 생년월일 입력 후 다음 단계(학교·학과 선택)로 이동.

**입력 조건**

| 항목 | 조건 |
|------|------|
| 이름 | 글자수 제한 내, 한글·영문 허용 |
| 생년월일 | 미래 날짜 입력 불가, 만 14세 미만 가입 차단 (운영 정책에 따라 조정) |

**예외 처리**

| 상황 | 결과 |
|------|------|
| 미래 생년월일 | 입력 차단 |
| 빈 입력 | "다음" 버튼 비활성 |

#### 학교·학과 선택

> 회원이 자신이 소속된 학교와 전공을 등록하여 학교 단위 커뮤니티에 참여할 수 있다.

**누가**: 가입 진행 중

**정상 흐름**
1. 대학 검색(키워드·지역·학제 필터)으로 본인 대학 선택
2. 선택된 대학의 계열 → 세부 전공 순으로 선택
3. 다음 단계(학생증 제출)로 이동

**예외 처리**

| 상황 | 결과 |
|------|------|
| 검색 결과 없음 | 빈 결과 안내 메시지 |
| 등록되지 않은 학교 | 학교 등록 요청 흐름 노출(운영 정책으로 정의) |
| 검색어가 너무 짧음 | 최소 글자수 안내 |

#### 학생증 제출

> 회원이 자신이 학생임을 증명하기 위해 학생증 사진을 제출할 수 있다.

**누가**: 가입 진행 중

**정상 흐름**
1. "카메라로 촬영" 또는 "갤러리에서 선택" 중 하나 선택
2. OS 권한 요청(카메라/사진)
3. 학생증 사진을 획득하여 업로드
4. 업로드 완료 시 검증 대기 상태로 전환

**입력 조건**

| 항목 | 조건 |
|------|------|
| 이미지 형식 | JPG / PNG |
| 용량 상한 | 운영 정책으로 정의 |
| 중복 제출 | 동일 이미지 중복 제출 차단 |

**예외 처리**

| 상황 | 결과 |
|------|------|
| 카메라/사진 권한 거부 | OS 설정으로 이동 안내 |
| 업로드 실패(인터넷 끊김) | 재시도 안내 |
| 동일 이미지 재제출 | "이전과 같은 이미지입니다" 안내 |

#### 학생증 검증 결과 처리

> 회원이 학생증 제출 후 결과(대기/승인/거절)를 확인하고 다음 단계로 진행할 수 있다.

**누가**: 가입 진행 중

**정상 흐름 (상태별)**

| 검증 상태 | 회원에게 보이는 결과 |
|----------|------|
| 대기 | "검토 중" 안내. 백그라운드 → 포그라운드 복귀 시 상태 자동 재조회 |
| 승인 | 자동으로 프로필 설정 단계로 이동 + 승인 알림 |
| 거절 | 거절 사유 표시 + "재제출" 버튼 노출 + 거절 알림 |

**정책**

- 검증 SLA: 영업일 기준 24시간 이내(운영 정책으로 확정)
- 운영시간 외 제출은 익영업일에 처리될 수 있음을 사전 안내

#### 학생증 재제출

> 학생증이 거절된 회원이 사유를 확인하고 다시 제출할 수 있다.

**누가**: 검증 거절 상태

**정상 흐름**: 거절 사유 표시 → "재제출" → 학생증 제출 흐름으로 회귀.

**정책**: 재제출 횟수 제한은 운영 정책으로 정의. 초과 시 고객지원 문의 안내.

#### 프로필 설정

> 학생증이 승인된 회원이 닉네임과 프로필 이미지로 자신을 표현할 수 있다.

**누가**: 가입 진행 중(검증 승인 직후)

**정상 흐름**
1. 닉네임 입력 → 입력 즉시 중복 여부 확인
2. 프로필 이미지 선택(선택 사항)
3. 소개·기타 정보 입력
4. "완료" → 푸시 알림 권한 안내로 이동

**입력 조건**

| 항목 | 조건 |
|------|------|
| 닉네임 | 2~20자(운영 정책 확정), 부적절한 단어 차단 |
| 프로필 이미지 | 형식·용량 제한, 선택 입력 |

**예외 처리**

| 상황 | 결과 |
|------|------|
| 닉네임 중복 | "이미 사용 중인 닉네임입니다" 안내 |
| 부적절한 단어 포함 | 차단 메시지 |
| 이미지 업로드 실패 | 재시도 안내 |

#### 푸시 알림 권한 안내

> 회원이 가입 마무리 단계에서 알림 수신 여부를 결정할 수 있다.

**누가**: 가입 진행 중(프로필 설정 직후)

**정상 흐름**: OS 권한 다이얼로그 표시 → 허용/거부 어느 쪽이든 다음으로 진행. 허용 시 알림 수신 등록.

**정책**: 거부한 사용자도 추후 마이페이지의 알림 설정에서 다시 활성화 가능.

#### 회원가입 중단 후 재개

> 가입 도중 앱을 종료하거나 이탈한 회원이 다음 진입 시 진행 단계로 자동 복귀할 수 있다.

**누가**: 가입 진행 중

**정상 흐름**: 미완료 가입자가 앱을 다시 열면, 진행 단계에 맞는 화면으로 자동 이동(자격증명·기본정보·학교·학생증·검증대기·거절·프로필 중 하나).

**예외 처리**

| 상황 | 결과 |
|------|------|
| 진행 상태가 알 수 없음 | 처음부터 시작 안내 |

### 4.2 로그인

#### 이메일·비밀번호 로그인

> 가입한 회원이 이메일과 비밀번호로 로그인할 수 있다.

**누가**: 비회원

**정상 흐름**
1. 이메일·비밀번호 입력
2. "로그인" 버튼 탭
3. 성공 시 홈 화면 진입

**입력 조건**

| 항목 | 조건 |
|------|------|
| 이메일 | 비어 있으면 시도 차단 |
| 비밀번호 | 비어 있으면 시도 차단, 표시/숨김 토글 제공 |

**예외 처리**

| 상황 | 결과 |
|------|------|
| 잘못된 ID 또는 비밀번호 | "로그인에 실패했습니다" (보안상 잘못된 ID/PW를 구분하지 않음) |
| 일시 정지 회원 | 정지 사유와 안내 표시 |
| 영구 차단·탈퇴 회원 | 로그인 불가 안내 |
| 인터넷 끊김 | 재시도 옵션 노출 |
| 로딩 중 버튼 중복 탭 | 1회만 시도되어야 함 |

#### 소셜 로그인

> 회원이 외부 계정(Google / Kakao / Naver / Apple)으로 별도 비밀번호 없이 로그인할 수 있다.

**누가**: 비회원

**정상 흐름 (공통)**
1. 제공자 인증 화면 호출
2. 사용자 인증 완료
3. 신규 사용자는 가입 흐름으로, 기존 사용자는 홈 화면 진입

**제공자별 동작 차이**

| 제공자 | 동작 |
|--------|------|
| Google | 구글 계정 선택 → 권한 동의 |
| Kakao | 카카오톡 앱 설치 시 카카오톡 우선, 실패 시 자동으로 웹 로그인 폴백 |
| Naver | 네이버 로그인 화면. 빠른 연타 충돌은 자동 1회 재시도로 해결 |
| Apple | iOS 13 이상 지원. 두 번째 로그인부터는 이름이 비어 들어오므로 첫 로그인의 이름이 유지되어야 함 |

**예외 처리**

| 상황 | 결과 |
|------|------|
| 사용자가 인증 취소 | 로그인 화면 잔류, 별도 메시지 없음 |
| 응답 15초 미응답 | "응답이 없습니다. 다시 시도해주세요" 안내 |
| 외부 사업자 약관 미동의 | 안내 메시지 |

### 4.3 자동 로그인·세션 유지

#### 자동 로그인

> 한 번 로그인한 회원은 명시적 로그아웃이나 장기 미사용이 아닌 한 다시 로그인 입력을 요구받지 않는다.

**누가**: 모든 사용자

**정상 흐름**: 앱 시작 → 자동 로그인 가능 여부 판단 → 가능하면 홈, 불가능하면 로그인 화면.

**예외 처리**

| 상황 | 결과 |
|------|------|
| 너무 오래 미사용 | 로그인 화면으로 이동 + "보안을 위해 다시 로그인해주세요" 안내 |

#### 세션 자동 갱신

> 회원이 사용 도중 세션이 만료되어 작업이 중단되는 일이 없어야 한다.

**누가**: 정상 회원

**정상 흐름**: 세션 만료 시점에 도달하면 사용자 인지 없이 자동으로 갱신 후 진행 중인 동작을 이어서 처리.

**정책**

- 동시에 여러 만료가 발생해도 갱신은 1회만 수행되어야 한다
- 갱신마저 실패한 경우 로그아웃 상태로 전환하고 로그인 화면으로 안내

### 4.4 로그아웃·탈퇴

#### 로그아웃

> 회원이 명시적으로 로그아웃하여 본인 정보를 디바이스에서 정리할 수 있다.

**누가**: 정상 회원

**정상 흐름**: 로그아웃 확인 → 로그인 정보 모두 폐기 → 알림 수신 해제 → 로그인/인트로 화면.

**예외 처리**

| 상황 | 결과 |
|------|------|
| 알림 수신 해제 실패 | 로그아웃 자체는 정상 진행 |

#### 회원 탈퇴

> 회원이 더 이상 서비스를 이용하지 않을 때 본인의 계정과 데이터를 정리할 수 있다.

**누가**: 정상 회원

**정상 흐름**
1. 탈퇴 사유 선택(선택 사항)
2. 확인 다이얼로그
3. 탈퇴 처리 + 탈퇴 완료 알림
4. 로그인 화면으로 이동

**정책**

- 탈퇴 후 작성 콘텐츠 처리(즉시 삭제 / 익명 처리 / 일정 기간 보관 후 삭제)는 운영 정책으로 정의
- 동일 이메일 재가입 가능 시점은 운영 정책으로 정의(예: 30일 후)

**예외 처리**

| 상황 | 결과 |
|------|------|
| 처리 중 실패 | 명확한 안내와 재시도 옵션 |

### 4.5 프로필·계정 관리

#### 프로필 수정

> 가입 후에도 회원이 닉네임·프로필 이미지·소개를 자유롭게 변경할 수 있다.

**누가**: 본인

**정상 흐름**
1. 닉네임 변경 시 입력 즉시 중복 검사
2. 프로필 이미지 변경 시 업로드 진행 → 완료
3. 소개·학과 등 정보 수정 후 저장

**정책**: 닉네임 변경 횟수·주기 제한이 있다면 사용자에게 사전 안내.

**예외 처리**

| 상황 | 결과 |
|------|------|
| 미저장 상태로 뒤로가기 | 확인 다이얼로그 노출 |
| 닉네임 중복 | "이미 사용 중인 닉네임입니다" 안내 |
| 이미지 업로드 실패 | 이전 상태 유지, 재시도 안내 |

#### 비밀번호 변경

> 이메일로 가입한 회원이 비밀번호를 변경할 수 있다.

**누가**: 본인 (이메일 가입자에 한함)

**정상 흐름**
1. 현재 비밀번호 확인
2. 새 비밀번호 입력
3. 저장 + 보안 알림 발송

**정책**: 새 비밀번호는 가입 시와 동일한 정책 적용. 이전 비밀번호와 동일한 값 차단(운영 정책).

#### 약관 동의 이력 조회

> 회원이 본인이 동의한 약관 이력을 조회할 수 있다.

**누가**: 본인

**정상 흐름**: 마이페이지 → 개인정보·보안 → 약관 동의 이력 → 항목별 동의 일시 표시.

## 5. 정책·규칙

### 5.1 가입 정책

| 항목 | 값 |
|------|------|
| 가입 가능 연령 | 만 14세 이상 (운영 정책으로 확정) |
| 이메일 중복 | 한 이메일 = 한 회원 계정 |
| 약관 동의 시각 | 모든 약관 동의는 시각과 함께 기록 |
| 약관 시행일 변경 | 기존 회원에게 재동의 요구 |

### 5.2 학생증 검증 정책

| 항목 | 값 |
|------|------|
| 검증 SLA | 영업일 기준 24시간 이내 (운영 정책으로 확정) |
| 검증 결과 통지 | 인앱 + 푸시 알림 |
| 재제출 횟수 제한 | 운영 정책으로 정의 |

### 5.3 닉네임 정책

| 항목 | 값 |
|------|------|
| 글자수 | 2~20자 (운영 정책으로 확정) |
| 중복 | 동일 닉네임 사용 불가 |
| 부적절 단어 | 차단 |
| 변경 횟수 | 운영 정책으로 정의 (예: 30일 1회) |

### 5.4 보안·세션 정책

| 항목 | 값 |
|------|------|
| 로그인 정보 저장 | 디바이스의 안전한 저장소에만 보관 |
| 장기 미사용 자동 로그아웃 | 운영 정책으로 정의 (예: 60일 미사용) |
| 차단/정지 안내 | 로그인 시 사유 표시 |

### 5.5 탈퇴 정책

| 항목 | 값 |
|------|------|
| 처리 방식 | 즉시 처리 vs 유예 후 처리 (운영 정책으로 정의) |
| 콘텐츠 처리 | 즉시 삭제 / 익명 처리 / 보관 후 삭제 (운영 정책으로 정의) |
| 재가입 가능 시점 | 운영 정책으로 정의 |

## 6. 알림 발송 명세

| 트리거 | 수신자 | 본문 (예시) | 카테고리 |
|--------|--------|-----------|---------|
| 학생증 검증 **승인** | 본인 | "학생증이 인증되었습니다. 가입을 마저 완료해주세요." | 시스템 |
| 학생증 검증 **거절** | 본인 | "학생증 인증이 거절되었습니다. 사유를 확인하고 다시 제출해주세요." | 시스템 |
| 일시 정지·영구 차단 처리 | 본인 | "회원님의 계정이 {일시 정지/차단}되었습니다. 사유: {사유}" | 시스템 |
| 비밀번호 변경 완료 | 본인 | "비밀번호가 변경되었습니다. 본인 변경이 아니라면 즉시 문의해주세요." | 보안 |
| 회원가입 환영(선택) | 본인 | "Claspeek에 오신 것을 환영합니다." | 마케팅/시스템 |
| 탈퇴 처리 완료 | 본인(이메일 또는 마지막 푸시) | "회원 탈퇴가 완료되었습니다." | 시스템 |

> 시스템·보안 카테고리 알림은 사용자가 마이페이지의 알림 설정에서 끌 수 없다. 카테고리 정의는 공통 정책 문서의 "알림 카테고리 정의" 참조.

## 7. 도메인 공통 예외

- 인터넷 끊김: 모든 단계에서 일관된 오류 메시지·재시도 옵션.
- 일시 정지·영구 차단 회원의 로그인 시도 처리는 사유와 함께 명확히 안내.
- 학생증 검토 시간이 길어지는 경우 새로고침/문의 안내가 노출.
