# 06. 다이어리

## 1. 도메인 정의

회원이 본인만 보는 비공개 일기를 작성·열람할 수 있는 도메인. 다이어리는 작성자 외에는 누구도 조회·수정·삭제할 수 없다.

## 2. 핵심 개념·용어

- **다이어리**: 회원이 본인의 감정·일상을 기록하는 비공개 글. 일자별로 작성한다.
- **다이어리 캘린더**: 작성한 다이어리가 어느 날에 있는지 한눈에 보여주는 월간 뷰.

## 3. 기능 요구사항

### 3.1 다이어리 둘러보기·읽기

#### 다이어리 캘린더 조회

> 회원이 본인이 작성한 다이어리가 어느 날에 있는지 한눈에 볼 수 있다.

**누가**: 본인

**정상 흐름**: 진입 시 월간 캘린더와 일자별 다이어리 마커 표시. 좌/우 스와이프로 월 이동.

#### 다이어리 목록 조회

> 회원이 본인의 다이어리를 시간순으로 둘러볼 수 있다.

**누가**: 본인

**정상 흐름**: 본인 작성 다이어리를 페이지 단위로 조회.

#### 다이어리 자세히 보기

> 회원이 본인이 작성한 다이어리 본문을 다시 읽을 수 있다.

**누가**: 본인

**정상 흐름**: 캘린더 일자 클릭 또는 목록 클릭 → 다이어리 본문 표시.

**예외 처리**

| 상황 | 결과 |
|------|------|
| 이미 삭제된 다이어리 | 안내 후 뒤로가기 |
| 타인의 다이어리 직접 접근 시도 | 거절 |

### 3.2 다이어리 작성·관리

#### 다이어리 작성

> 회원이 본인의 일상·감정을 자유롭게 일기로 남길 수 있다.

**누가**: 정상 회원

**정상 흐름**: 제목·내용·(이미지 첨부) 입력 → 저장.

**입력 조건**

| 항목 | 조건 |
|------|------|
| 제목·내용 | 길이 제한 내, 빈 내용 차단 |
| 동일 일자 다중 작성 | 운영 정책으로 정의 |
| 부적절한 단어 차단 | 비공개 콘텐츠이므로 미적용 가능(운영 정책) |
| 이미지 첨부 | 운영 정책으로 허용 여부·개수·용량 정의 |

**예외 처리**

| 상황 | 결과 |
|------|------|
| 빈 내용 저장 시도 | 차단 |
| 작성 중 백그라운드 → 복귀 | 입력 내용 유지 또는 임시 저장(운영 정책) |

#### 다이어리 수정

> 작성자가 본인의 다이어리를 수정할 수 있다.

**누가**: 본인

**정상 흐름**: 본인 다이어리 → 수정 → 저장.

#### 다이어리 삭제

> 작성자가 본인의 다이어리를 삭제할 수 있다.

**누가**: 본인

**정상 흐름**: 삭제 확인 → 캘린더 마커·목록에서 즉시 제거.

## 4. 알림 발송 명세

| 트리거 | 수신자 | 본문 (예시) | 카테고리 |
|--------|--------|-----------|---------|
| 작성 리마인더(예: 매일 21시) | 본인 | "오늘 하루는 어땠나요? 다이어리에 기록해보세요." | 리마인더 |

**공통 정책**
- 다이어리는 비공개이므로 타인의 활동에 의한 알림은 발생하지 않는다.
- 리마인더 시각·요일 정책은 운영팀이 결정. 사용자가 마이페이지의 알림 설정에서 끌 수 있어야 한다.

## 5. 정책·규칙

| 항목 | 값 |
|------|------|
| 비공개 원칙 | 다이어리는 어떠한 경우에도 타인에게 노출되지 않음 |
| 타인 접근 차단 | 다이어리 식별자가 노출되더라도 작성자가 아니면 접근 거절 |
| 이미지 첨부 | 운영 정책으로 허용 여부·개수·용량 정의 |

## 6. 도메인 공통 예외

- 매우 긴 본문(예: 5,000자 이상) 입력 시 저장·표시·스크롤 성능.
- 작성 도중 앱 강제 종료 후 재진입 시 임시저장 동작 여부는 운영 정책으로 정의.
